# 협업 규칙 (R&R) — 누가 무엇을 하는가

> 작성: 2026-08-21. 사용자는 SAP FI 컨설턴트 경험이 있는 프로그래밍 비전문가로, 요청을 비유(집짓기·제품 제조)로 표현할 수 있다.
> SAP 프로젝트에 비유하면: **사용자 = 현업 프로세스 오너이자 결재권자**(요구 정의, 단계별 사인오프), **Claude = 구현 컨설턴트 + 개발팀**(설계·개발·테스트·문서화 전부).

## 사용자(제품 오너)가 하는 것

- **요구와 의도 제공** — 비유로 말해도 됨. Claude가 기술 요구사항으로 번역해 확인받는다.
- **결정과 승인(사인오프)** — Phase 게이트 승인/반려, 선택지 중 결정. Claude는 선택지+트레이드오프+추천안까지만.
- **눈으로 하는 검수** — 시각화 확인, 실행 결과 확인, "이게 내가 원한 게 맞다/아니다" 판정.
- **도메인 지식 제공** — 자료의 성격, 업무 맥락 등 Claude가 알 수 없는 것.

## 사용자가 직접 해야만 하는 것 (Claude가 대신할 수 없음 — 보안 원칙)

- 계정 생성·로그인 (Jina 키 발급, ChatGPT/Claude OAuth 로그인, Neo4j 계정 등)
- 비밀번호·API 키·시크릿을 `.env` 파일에 입력하는 행위 (Claude에게 키를 채팅으로 알려주지 말 것)
- 결제·구독·약관 동의
- GitHub 공개 push 등 외부 공개 행위의 최종 실행 (Claude는 준비까지, 실행은 확인 후)

→ 이런 액션이 필요한 시점마다 Claude가 **"사용자 액션 필요"** 라고 명시하고 단계별 안내를 제공한다.

## Claude가 하는 것

- 모든 코드 작성·수정·실행·테스트 검증
- 조사와 사실 검증(웹), **각 분야 전문가 패널(Workflow 에이전트) 상시 투입** — 실질적 요청·질의마다
- 문서 작성·갱신 (PROCESS / PRD / TECH-SPEC / ROADMAP / DECISIONS / 인터뷰 기록)
- 기술 결정의 선택지·트레이드오프·추천안 제시
- 전문용어를 비유·풀이와 함께 설명 (프로그래밍 지식을 전제하지 않음)
- 매 응답 끝 `현재 위치: Phase X.Y / 다음 액션` 표시

## 커뮤니케이션 방식

- 사용자 비유 → Claude가 기술 번역 → 사용자 확인, 순서로 오해를 방지한다.
- 중요한 내용은 반드시 문서로 남긴다 (대화는 휘발되지만 docs/는 남는다).
- 정보가 부족하면 추측하지 않고 질문한다. 질문은 한 번에 3~5개, 선택지와 추천 기본값 포함.
