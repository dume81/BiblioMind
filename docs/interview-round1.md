# 인터뷰 1라운드 정리본 — 비블리오마인드(BiblioMind) (GraphRAG_1st)

> 상태: **사용자 확인 대기** | 작성: 2026-08-21
> 사용자의 1라운드 답변을 전문가 4인(PM·솔루션 아키텍트·LLM 통합·데이터 파이프라인) 분석으로 검증·정리한 문서.
> 사용자 승인 시 이 내용이 PRD(Phase 0.2~0.5)의 입력이 된다.
> 전문가 원본 보고서 4건은 세션 스크래치패드에 있으며, 핵심은 본 문서에 반영됨.

## 1. 제품 한 줄 정의

**"내 자료(PDF·이미지·웹페이지)를 지식그래프로 변환해 로컬 Neo4j에 쌓고, 디스코드로 질문하면 답변이 지나간 노드·관계 경로가 크롬의 3D 그래프에서 하이라이트되는 로컬 GraphRAG 도구"** — GitHub(dume81/GraphRAG_1st)에 공개되어 타인도 클론해 자기 환경에서 재현 가능.

핵심 아이덴티티: 답을 주는 도구가 아니라 **"답의 근거 경로를 눈으로 보여주는 도구"**. 일반 RAG의 "출처 문서 링크" 수준을 넘어, 답변이 실제로 거쳐간 서브그래프를 3D 공간에서 보여주는 설명가능성(explainability)이 차별의 본질.

## 2. 요청 유형 판별 (PROCESS.md 유형 표 기준)

**새 프로덕트(파이프라인 + 검수·시각화 UI 복합).** 1~2단계(추출·KG 생성)는 시스템/자동화 조정 적용(시나리오를 "트리거 → 처리 → 결과" 형식, 실패·재시도·멱등성 점검 필수), 3단계 이후는 기존 시각화 앱(visualization-3d) 연동·확장으로 다룬다.

## 3. 전체 흐름 (End-to-End 여정)

| 단계 | 행위 | 산출물/상태 |
|---|---|---|
| 1. 소스 등록 | PDF·이미지 업로드 또는 URL 입력(+동일 도메인 크롤링, 페이지 상한 설정: 예 100→10) | 처리 대기열 |
| 2. 추출·변환 | 문서→텍스트 추출, URL→Jina Reader로 MD 변환 | `Input/` 폴더, 타임스탬프 명명 저장 |
| 3. KG 생성 | req_node_relation.txt({schema} 주입) + LLM 호출 | Neo4j 호환 KG JSON |
| 4. 검수-전 | KG JSON을 기존 3D 앱에 드래그앤드롭, 눈으로 확인 (승인/반려만, 편집 없음) | 승인 또는 반려 |
| 5. Neo4j 주입 | 승인분을 로컬 데스크탑 Neo4j에 적재 | 그래프 DB 갱신 |
| 6. 검수-후 | 3D 앱을 Neo4j 소스 모드로 전환해 확인 | 운영 상태 그래프 |
| 7. 질의응답 | 디스코드에서 질문 → 그래프 검색 → LLM 답변 | 디스코드로 답변 수신 |
| 8. 경로 하이라이트 ★ | 답변에 사용된 노드·관계가 3D 시각화에서 하이라이트 | "지식 경로" 시각 피드백 |
| 9. 반복·성장 | 새 자료를 계속 추가 | 개인 지식그래프의 성장 |

MVP를 이 여정의 어디까지로 할지는 미정 — 2라운드 결정 사항 (아래 6절).

## 4. 확정 요구사항 (1라운드 답변 기준)

- **플랫폼**: 크롬 브라우저에서 여는 로컬 웹앱 (기존 visualization-3d의 연장으로 추정 — "크롬 웹 한정"이 확장프로그램을 뜻하는지는 확인 필요)
- **사용자**: 1차 = 제작자 본인(로컬 도구). 2차 = GitHub 클론 사용자(자기 자격증명·환경으로 재현 가능해야 함)
- **자료 추출**: ① 문서 = PDF/이미지 ② 웹 = 같은 도메인 전체 크롤링 + 페이지 수 상한 옵션, Jina AI Reader로 MD 변환. 산출물은 `Input/` 폴더, 일시 포함 명명(YYYYMMDDHHMMSS_제목). 저장공간 1TB+로 용량 걱정 없음
- **KG 생성**: 1차는 ChatGPT 유료 구독 경유로 제한. req_node_relation.txt 프롬프트 사용, Neo4j 호환 JSON({"nodes":[...], "relationships":[...]}) 반환. 로컬 LLM Gemma는 KG 생성 품질 검증 후 후속 검토
- **검수**: 눈 확인만(승인/반려), 노드 편집·병합 없음. 검수 전 = JSON 파일 라이트 확인, 검수 후 = Neo4j 기반 확인. 두 모드 모두에서 하이라이트 피드백 기능은 동일하게
- **AI챗**: 자체 채팅 UI를 만들지 않고 디스코드 연결로 해결 (효율 중시)
- **배포**: 로컬 도구이되 github.com/dume81/GraphRAG_1st 에 push하여 오픈소스 공개

## 5. 전문가 검증 결과

### 5-1. 그대로 가면 되는 것 (실현 가능성 확인됨)

1. **ChatGPT 구독으로 프로그램에서 모델 호출 — 공식 경로 존재.** Codex CLI/SDK에 ChatGPT 계정으로 로그인(`codex login`)하면 모델 호출이 구독 요금제에서 차감된다. `codex exec`(비대화 모드)는 "파이프라인에서 반복 호출" 용도로 공식 지원되고, outputSchema(JSON Schema)로 KG JSON 형식을 강제할 수 있다. 2026-07 Codex·ChatGPT Work 통합으로 지식그래프 생성 같은 비코딩 워크플로도 공식 범위다. **추가 비용 0원으로 2단계(KG 생성)가 성립한다.** 단 레이트리밋 존재: Plus 기준 5시간당 모델 티어별 10~2,000 메시지 + 주간 한도 → 체크포인트형 배치 설계로 대응 가능.
2. **하이라이트의 기술 토대가 이미 있다.** 기존 앱의 Neo4j 모드는 노드/관계를 elementId로 식별하므로(server/core/mapper.js 확인), 백엔드가 검색한 서브그래프의 id와 화면의 id가 매칭된다. 정규화 계층(canonicalGraph.js)도 파이프라인에서 재사용 가능.
3. **크롤링 비용은 사실상 무료.** Jina 무료 API 키 = 500 RPM + 무료 토큰 10M(약 $0.02/1M 출력 토큰 종량제) → 100페이지급 크롤링은 무료 토큰으로 충분.
4. **Gemma 계획도 유효.** 최신은 Gemma 4(2026-04, Apache 2.0). Ollama로 Windows에서 구동되며 structured output으로 KG JSON 스키마 강제 가능 — "검증 후 도입" 계획과 정합. 단 변형 선택(E4B~31B)에 PC RAM/GPU 사양 확인 필요.

### 5-2. 조정이 필요한 것 (사실 교정 — 요구사항 자체는 유지, 실현 방식 변경)

1. **"디스코드 + OAuth"만으로는 챗이 성립하지 않는다.** 질문을 수신·응답하려면 **디스코드 봇**(Developer Portal에서 생성, 봇 토큰 + Gateway 상시 접속)이 필요하다. OAuth는 신원 확인·봇 초대 권한용일 뿐이다. OpenAI 공식 디스코드 커넥터는 존재하지 않으며, 2026-08 베타 "Sign in with ChatGPT"는 신원 전용(모델 호출 불가)이다. 현재 사용 중이라는 "ChatGPT OAuth + 디스코드"의 실체는 OpenClaw류(로컬 게이트웨이 + 디스코드 봇 + Codex OAuth)로 추정되나 확인 필요. → 봇 방식이면 슬래시 커맨드(`/ask 질문`)가 설정 부담 최소로 권장.
2. **Jina Reader는 "단일 URL → MD" 변환기다.** 같은 도메인 전체 크롤링 기능은 없다. 링크 발견(sitemap.xml 파싱 → 실패 시 링크 요약 옵션 기반 BFS) + 페이지 상한 적용은 우리가 직접 구현한다. robots.txt 존중·요청 간격 등 크롤링 예절 기본 탑재.
3. **파일명에 URL을 그대로 쓸 수 없다.** URL의 `: / ?` 등은 Windows 파일명 금지 문자다. 변형 제안: `YYYYMMDDHHMMSS_도메인슬러그_경로슬러그_해시8자.md` + **원본 URL·수집 시각은 파일 안 YAML 프론트매터에 보존** (의도인 "일시+출처 식별"은 그대로 유지됨).
4. **하이라이트는 UI 기능이 아니라 아키텍처 결정이다.** "거쳐간 경로"는 질의응답이 명시적 그래프 탐색(Neo4j 검색 → 서브그래프를 LLM 컨텍스트로)을 거칠 때만 존재한다. 따라서 **상시 실행되는 로컬 백엔드**(디스코드 봇 + Neo4j 검색 + 시각화 앱으로 하이라이트 푸시)가 신규 핵심 컴포넌트가 되며, 임베딩 없이 full-text 검색 + k-hop 확장으로 1차 구현 가능하다.
5. **숨은 전제의 명시화**: 질문은 디스코드에서, 하이라이트는 크롬 3D 앱에서 일어나는 크로스-서페이스 경험이므로, **3D 앱이 열려 있어야 하이라이트가 보인다**. 또한 하이라이트 루프는 로컬 실행 전제(Vercel 배포본은 시각화 단독 시연용).
6. **재실행 중복(멱등성) 처리 필요**: 타임스탬프 명명은 재실행마다 새 파일을 만들어 같은 내용이 KG·Neo4j에 중복 주입될 수 있다. URL 정규화 + 원장(ledger) 기반 스킵 + `--force` 재수집 옵션을 1차 기본값으로 제안.

### 5-3. 구조 관련 전문가 권고 (설계 단계에서 확정할 사안)

- **저장소 전략**: 기존 GraphRAG_1st에 `pipeline/`(추출+생성+주입), `ragserver/`(봇+검색+하이라이트 허브), `shared/`(스키마 공유) 를 추가하는 **모노레포** 권장 — 클론 1회로 전체 제품 재현.
- **MVP 경계에 대한 PM 권고**: "B안(Neo4j 주입까지)을 골격으로 하되, 최대 불확실성인 하이라이트 루프를 예시 JSON 수동 주입 상태에서 얇은 E2E 스파이크로 선행 검증"하는 하이브리드. 이유: 이 제품에서 가장 불확실하면서 가장 중요한 것이 하이라이트이고, 가장 확실하면서 덜 중요한 것이 파이프라인이므로, 확실한 것부터 다 만들고 불확실한 것에 나중에 도달하는 순서는 리스크 발견 시점을 최악으로 늦춘다.

## 7. 대화 인터페이스 검증 결과 (2026-08-21 추가)

사용자 질문("지금 쓰는 Claude 앱이나 ChatGPT 앱이 이 흐름을 수행할 수 있나?")에 대한 3개 경로 병렬 웹 검증 결과:

| 경로 | 판정 | 핵심 근거 |
|---|---|---|
| **Claude 앱 (Claude Code/Desktop) + 로컬 MCP** | ✅ **성립** | 로컬 stdio MCP 공식 지원. Neo4j 공식 MCP 서버 존재, "도구 → 로컬 앱 푸시" 선례(Blender MCP) 확인. 구독 범위 내 무과금. 구축 약 하루 |
| **ChatGPT 데스크탑 앱(Codex 표면)/Codex CLI + 로컬 MCP** | ✅ 조건부 성립 | 데스크탑 앱·CLI는 로컬 stdio MCP 공식 지원(`~/.codex/config.toml`), Plus 로그인만으로 사용. 단 **웹/모바일 ChatGPT는 불가**(원격 HTTPS 전용, 터널링은 보안 위험) |
| **디스코드 + OpenClaw** | ⚠️ 조건부 성립 → **배제 확정** | 기술적으로 가능하나 2026년 초 대규모 보안 사고 이력, 클론 사용자 재현 부담 과중. 사용자 결정 규칙에 따라 배제 |

**핵심 발견**: 하나의 로컬 MCP 서버(도구 2개 — ① 그래프 검색: Neo4j 검색 후 서브그래프+id 반환 ② 하이라이트: id 목록을 시각화 앱에 푸시)를 만들면 **Claude와 Codex 클라이언트 양쪽에 동일하게 연결**된다. 클론 사용자는 자신이 가진 구독으로 재현할 수 있어 오픈소스 재현성이 디스코드 방식보다 오히려 좋아진다. 하이라이트는 LLM 지시 준수에 의존하지 않도록 검색 시점에 백엔드가 결정적으로 푸시하는 설계를 채택한다.

## 8. 답변 5건 게이트 검증 결과 (2026-08-21 추가)

사용자의 후속 답변 5건(① 인터페이스 해소 확인 ② 하이라이트 정의 ③ 파일명 규칙 ④ 검수 흐름 수정 ⑤ 하이라이트 결과물 스펙)에 대한 전문가 3인 게이트:

| 검증자 | 대상 | 판정 | 핵심 |
|---|---|---|---|
