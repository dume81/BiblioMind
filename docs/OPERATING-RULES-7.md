# 오너 상시 규칙 — **축소 채택안 7조** (승인 대기)

> 2026-08-22 · 18조 초안([OPERATING-RULES-draft.md](OPERATING-RULES-draft.md))을 시뮬레이션([OPERATING-RULES-simulation.md](OPERATING-RULES-simulation.md))으로 검정한 뒤 **값이 증명된 것만 남긴 판**.

> **2026-08-22 개정**: 오너 지시로 **전문가 투입이 제1조로 신설**되어 이 문서의 7조가 **8조**가 됐다. 정본은 워크스페이스 루트 `CLAUDE.md` 말미(최우선 규칙 자체는 `~/.claude/CLAUDE.md` 사용자 전역). 아래 조문 번호는 개정 전 기준이며 근거·검정 결과 참조용으로 유지한다 — 조문 1→2, 5→3, 6→4, 9→5, 10→6, 16→7, 17→8.
> **반영 완료 (2026-08-22, 오너 회신 "① A")** — 정본은 워크스페이스 루트 `CLAUDE.md` 말미 8조 절. 이 문서는 그 조문들의 **근거·기각 사유·미차단 범위** 참조본으로 남는다.

## 왜 7조인가 — 근거 3줄

- 실제 턴 6개를 18조 아래에서 재생한 결과, **결함을 검출한 조문은 5·6 둘뿐**이고 나머지 16조의 검출 성과는 **0건**이었다.
- 18조 전체 적용 시 착수 턴당 **+44줄**이 붙는데 그중 오너 의사결정에 쓰이는 것은 **19줄(8.3%)**뿐이다.
- 7조로 줄이면 턴당 순증이 **+14줄**로 떨어지고, 검출 성과 2건은 그대로 남는다.

## 제1조 — 착수 판정 *(축소·재정의)*

매 턴 첫 줄에 **`[착수]` / `[비착수]`** 라벨과 근거 반 줄을 적는다.

**착수 = Claude가 저장소 추적 파일을 바꾸거나 커밋하는 턴, 또는 오너 결정을 요청하는 턴.** 나머지는 전부 비착수.

- `data/runtime/` 등 **런타임 산출물 변경은 착수로 세지 않는다** — 오너가 비블리오마인드에 질문 1건을 던질 때마다 검색 기록 파일이 쓰이므로, 이를 착수로 세면 완성 후 일상 질의 전건이 결재 대상이 된다.
- **규칙이 요구한 산출물을 쓰는 행위 자체는 착수로 세지 않는다** (의례가 의례를 부르는 것 방지).

> **18조판에서 바뀐 것**: 발동 조건에서 "파일 생성·수정·삭제"를 "**추적 파일** 변경·커밋"으로 좁히고, 런타임·의례 산출물 예외를 명시. 원안은 양쪽으로 빗나갔다 — 제품 사용 턴을 착수로 잡고, 정작 6에이전트 패널만 띄우는 가장 비싼 턴은 비착수로 놓쳤다.

## 제5조 — 합격선 정본 *(+1문)*

`ROADMAP.md`·`MAINTENANCE-PLAN.md`에 완료 조건이 있으면 **그것이 합격선**이다. 없는 과업만 새로 쓴다.

명제마다 **측정 수단**과 **판정 주체**(Claude / 오너)를 붙인다. "잘 동작한다"류 금지.

**추가**: 완료 조건은 **파일 경로 · 실행 명령 · 수치 임계값** 중 하나 이상으로 쓴다 — 그래야 "그 파일이 실제로 있는가"를 기계가 검사할 수 있다.

> ### 개정 (2026-08-22 오너 승인 — 워크스페이스 `CLAUDE.md` 제3조가 정본)
>
> *"중 하나 이상"* → **"임계값과 그 단위·분모·직전 실적을 전부"**. 임계값은 파일 경로·실행 명령·수치 중 무엇으로 표현해도 되나 **직전 실적과 같은 단위**여야 하고, 직전 실적이 없으면 `없음(신규)`이라 **명기**한다(빈칸 금지).
>
> **개정 근거 — 형식상 완전한데 퇴행을 못 잡은 실사례**: M4 합격선 5번은 *"소요 ≤10초"* 로 임계값·측정 수단·판정 주체가 모두 있었다. 그러나 **직전 실적 5.6초 칸이 없어** 실측 6.9초가 **+23% 퇴행**이라는 사실이 종료 보고에서 빠질 뻔했고, 제1조 반박 렌즈로만 잡혔다. ⇒ **임계값 단독으로는 "느려졌는데 통과"를 막지 못한다.**
>
> **반대 방향 실증**: 같은 날 A1·자동 실행 채널 두 과업에 개정안 형식을 실제로 적용한 결과, *"뮤테이션 생존 5건"* 을 숫자로만 넘기지 않고 **동치 1건 + DB 의존 4건**으로 성격을 갈랐다(`PREVENTION-MECHANISM.md` §4).
>
> **비용**: 합격선 표에 칸 1개 추가. 신규 과업은 `없음(신규)` 표기가 오히려 *"이것은 처음 재는 값"* 임을 드러내는 정보가 된다.

## 제6조 — 완료 선언

종료 보고에 **[명제 / 임계값 / 실측값 / 판정]** 대조표를 낸다.

판정은 **달성 · 미달 · 미측정 · 오너판정대기** 4값. **미달·미측정이 1건이라도 있으면 "완료"가 아니라 "부분 완료 — 미달 N건"** 으로 쓴다.

> **이 조문이 오늘 실제로 잡아낸 것 2건**: ① "M0 게이트 마감" 보고 — 실제로는 TECH-SPEC 개정 0/4 ② "유지보수 M1" 커밋 — 실제로는 `tools/check-keywords` 미작성. **7조 전체를 통틀어 유일하게 하드 증거를 낸 조문이다.**

## 제9조 — 주장 등급 *(대상 확장)*

수치 · 파일 경로 · 인용문 · 인과 주장 · **외부 화면·UI 명칭·버전 의존 정보**에 다음 중 하나를 붙인다.

| 등급 | 조건 |
|---|---|
| **[실측]** | 재현 가능한 명령을 실제로 실행함 |
| **[문서]** | 절대경로:행을 실제로 읽음 |
| **[추정]** | 산출 근거를 함께 적음 |
| **[미확인]** | 확인하지 않음 — **외부 화면·UI 명칭은 이것이 기본값** |

읽지 않은 파일의 내용을 진술하지 않는다.

> **18조판에서 바뀐 것**: 등급 대상이 파일·수치에 갇혀 있어 외부 서비스 화면이 사각지대였다. 오늘 Aura 콘솔 메뉴명을 옛 명칭으로 단정한 사고가 이 확장으로 막힌다.

## 제10조 — 부재 명시

조사했으나 못 찾으면 `확인 불가 — 조사 범위 X / 없었던 것 Y` 형식으로 쓰고 **확보 방법 1개**를 붙인다. 빈칸을 추론으로 채우지 않는다.

## 제16조 — 결정 요청 8요소 *(6→8)*

오너에게 결정을 올릴 때 다음을 갖춘다.

| # | 요소 |
|---|---|
| 1 | 결정할 것 |
| 2 | 선택지 2~3 |
| 3 | 각 결과 · 비용 · 되돌리기 |
| 4 | 추천안 + 사유 |
| 5 | 안 정하면 막히는 것 |
| 6 | 회신 형식 |
| **7** | **기결정 확인** — `[문서] 경로:행` 또는 `무적중`. **DECISIONS·TECH-SPEC·코드를 실제로 검색한 뒤 적는다** |
| **8** | **확정분 · 미결정분 분리** — 이미 정해진 부분과 정할 부분을 나눠 적는다 |

한 번에 3~5건, 초과는 이월. **단 오너가 "전량"·"누락없이"를 명시하면 상한을 적용하지 않는다.** 결정 대기 중에는 그 분기 이후 작업을 진행하지 않는다.

> **18조판에서 바뀐 것**: 7·8번 신설. 오늘 두 번(잔상·한글화) 오너가 정정하신 실수를 **초발에서 막는 유일한 경로**다. 상한 단서는 원안이 오너 지시("누락없이")를 이기도록 규정돼 있던 결함을 수리한 것.

## 제17조 — 결정 기록

오너 회신 · 게이트 승인 · 반려는 **그 턴 안에** `DECISIONS.md`에 **[날짜 · 결정 · 근거 · 미채택 대안]** 1항목으로 기록하고, 상단 인덱스 표에 1줄을 더한다.

> **실증**: 오늘 오너가 폐기하신 "② 잔상 처리 A안"이 채팅에서만 폐기되고 `MAINTENANCE-PLAN.md`에는 **그대로 남아 있었다.** 이 조문이 발효 중이었다면 생기지 않았을 불일치다.
