## 1. 문제 정의

흩어진 자료(PDF·이미지·웹페이지)를 지식으로 엮어 활용하려면 수작업 정리가 필요하고, 일반 RAG 챗봇은 답변의 근거를 "출처 문서 링크" 수준으로만 보여주기 때문에 **답이 어떤 지식 연결(노드와 관계)을 거쳐 나왔는지 확인·검증할 수 없다**. 이 제품은 자료를 지식그래프로 자동 변환해 Neo4j(AuraDB 클라우드 인스턴스 — 2026-08-21 전환)에 쌓고, AI챗으로 질문하면 답변이 거쳐간 노드·관계 경로를 3D 시각화에서 하이라이트해 **"답의 근거 경로"를 눈으로 검증**할 수 있게 한다. 답을 주는 도구가 아니라 **답의 근거 경로를 보여주는 도구**가 핵심 아이덴티티다.

## 2. 타겟 사용자

- **1차: 제작자 본인** — Windows 11 데스크탑, ChatGPT Plus·Claude 구독 보유, Neo4j AuraDB 클라우드 사용(무료 인스턴스 생성 예정 — 로컬 설치 불요, 2026-08-21 전환), 프로그래밍 비전문가(SAP FI 컨설턴트 경험). 최소한의 조작으로 "자료 → 그래프 → 검수 → 질문·검증" 루프를 반복하며 개인 지식그래프를 키우고 싶어 한다. 추가 비용 없이 기존 구독을 재활용하는 것을 중시한다.
- **2차: GitHub 클론 사용자** — github.com/dume81/GraphRAG_1st 을 클론해 자기 환경에서 재현하는 사람. 지원 수준은 **"재현 가능하게 해두는 대상"**: README 설치 가이드 + 설정 외부화(.env)까지 보장하고, 개별 트러블슈팅 지원은 범위 밖. 자기 구독(Claude 또는 ChatGPT)과 자기 Neo4j(AuraDB 무료 인스턴스 또는 로컬 — 코드가 URI 기반이라 양쪽 동작)로 재현한다.

## 3. 운영 원칙과 핵심 시나리오

### 운영 원칙

- **조작 원칙 — "챗이 조종석, 크롬 3D 앱은 화면"** (사용자 확정): 수집·생성·검수 표시·승인/반려·주입·자료 제거·질문까지 반복 작업의 모든 조작은 Claude/Codex 챗 명령으로 수행하고, 3D 앱은 결과를 보여주기만 한다. 파일 복사·붙여넣기, 드래그앤드롭, Neo4j에서의 별도 수동 작업은 없어야 한다. **1회성 설치 액션만 예외**: Neo4j AuraDB 인스턴스 생성(2026-08-21 전환 — 로컬 설치에서 변경), MCP 등록, 구독 로그인, Jina 무료 키 발급, 추출용 구성 요소 설치(OCR은 WASM 채택으로 현재 불필요 — 언어팩 최초 1회 자동 다운로드만 존재). (이 목록이 유일한 예외 목록이며 README가 이를 안내한다)
- **실패 보고 원칙**: 모든 챗 명령 도구는 결과 요약(성공 n건·실패 m건·실패 사유·재시도 방법)을 챗 응답으로 반환한다 — 사용자가 로그 파일을 열어보는 일이 없어야 한다.
- **데이터 취급 고지**: S2의 문서 추출은 로컬에서만 일어난다. 단, **S3의 KG 생성 시 자료 본문이 선택한 엔진(Codex/Claude)의 클라우드로 전송**되며 해당 구독 계정의 데이터 정책이 적용된다. **또한 주입된 그래프 데이터는 Neo4j AuraDB 클라우드에 저장된다(2026-08-21 전환)** — Aura 무료 인스턴스는 3일 무(無)쓰기 시 자동 일시정지되고 일시정지 30일 경과 시 인스턴스가 영구 삭제되나, 원본 진실은 로컬(Input/·Reviewed/)이므로 인스턴스 재생성 + 재주입으로 완전 복구된다. 민감·기밀 자료 투입 시 이 점을 인지해야 하며, README에 동일 고지를 포함한다.
- **언어 전제**: 1차 자료와 질문은 한국어 중심, 영어 혼재 허용. 노드 이름의 언어 규칙(원어 유지 등)은 스키마 지시문에 포함해 일관성을 확보한다. 교차 언어 검색(영어 자료에 한국어 질문)은 1차 범위 밖(후순위).
- **목표 규모·성능 기대 (1차)**: 자료 수백 건, 노드 수천 개 규모를 전제한다. 이 규모에서 전체 재빌드 수 분 이내, 질문→하이라이트 표시 10초 이내면 허용. 초과 규모의 성능은 1차 범위 밖.
- **공개 저장소 위생**: 라이선스는 기존 저장소의 **MIT 유지**(의존성은 MIT 호환 우선). **수집·생성 데이터(Input/, Generated/, Reviewed/, Rejected/, 원장 파일)는 저장소에 커밋하지 않는다(.gitignore 필수)** — 커밋되는 데이터는 명시적으로 선정한 예시 데이터뿐이다.

### 핵심 시나리오

> S6이 이 제품의 존재 이유다. S1~S5는 S6을 성립시키는 공급 파이프라인이며, **S6은 동시에 "주입 후 의미 검수"라는 필수 절차를 겸한다**.

- **S1 (웹 자료 수집)**: 사용자가 URL을 입력해 실행하면(페이지 상한은 선택 인자, **기본값 10**, 시작 페이지를 포함한 "시도한 페이지 수" 기준) → 같은 등록 도메인(하위 도메인 포함)의 페이지를 시작 페이지에서 가까운 순(BFS)으로 상한까지 발견하고(robots.txt 존중, 요청 간격 준수), 각 페이지를 Jina Reader로 마크다운으로 변환해 → `Input/`에 저장한다. **파일명 규칙**: `yyyymmddhhmmss_메인이름_pNN.md` — 타임스탬프는 실행(배치) 시작 시각으로 1회 고정 + 실행 내 순번, **메인이름 = 등록 도메인의 대표 이름**(`bibliomind.com`·`blog.bibliomind.com`·`bibliomind.co.kr` 모두 → `bibliomind`). 원본 URL·페이지 제목·수집 시각은 파일 첫머리 머리말(YAML 프론트매터)에 기록한다. **"이미 수집된 페이지" = 정규화된 URL 기준으로 MD 저장에 성공한 페이지**(정규화 규칙은 TECH-SPEC)이며 재실행 시 건너뛴다(`--force`로 강제 재수집). **실패한 페이지는 실패로 기록되고 재실행 시 자동 재시도**된다.
- **S2 (문서 자료 수집)**: 사용자가 PDF/이미지를 입력하면 → **로컬에서만** 텍스트를 추출해 → S1과 같은 규칙으로 `Input/`에 저장한다(메인이름 자리 = Windows 금지 문자를 제거한 원제목, 원제목 전체는 프론트매터 보존). **베스트에포트의 정의**: 스캔본·이미지는 추출 결과가 비거나 저품질이어도 오류가 아니며, 그 사실을 프론트매터에 표시한 채 파일을 생성한다.
- **S3 (KG 생성)**: 사용자가 챗에서 생성을 지시하면 → `Input/` 자료가 스키마 지시문에 따라 Neo4j 호환 KG JSON으로 변환되어 `Generated/`에 저장된다. **처리 단위: Input 파일 1개당 KG JSON 1개** — 이것이 승인·반려·재빌드 제외의 기본 단위다(긴 자료는 내부적으로 나눠 처리하더라도 산출물은 파일당 1개). **재실행 시 미생성 Input만 처리**한다(`--force` 예외). 한 엔진이 사용량 한도에 걸리면 **다른 엔진으로 자동 전환해 계속하고**(전환 사실과 파일별 생성 엔진은 결과 요약에 보고), **두 엔진 모두 한도로 중단되면 사용자가 같은 명령을 다시 실행해 재개**하며, 완료된 파일은 다시 생성하지 않고 `Generated/`에는 완전한 JSON만 놓인다(불완전 산출물은 검수 대상에 나타나지 않음). **엔진 선택**: **시작 엔진**은 설정 파일로 정하고, 챗 명령에서 지정하면 그 실행에 한해 우선한다. 한도 소진 시 상호 전환은 위 규칙을 따르며 끄는 옵션(전환 없이 고정)을 제공한다. **스키마 관리 — 도메인 스키마의 AI 자동 도출 (2026-08-21 요구 변경)**: 허용 노드·관계 유형(도메인 스키마)을 사용자가 미리 정의하거나 편집하지 않는다. KG 생성 시 **AI가 자료의 도메인을 분석해 적합한 유형을 스스로 도출**하되, **전역 스키마의 기존 유형을 우선 재사용**하고 부족한 유형만 명명 규칙에 맞게 신규 도출한다. 신규 유형은 생성 결과 요약에 보고되고 전역 스키마 파일에 자동 등재된다(버전 증가). 초기 전역 스키마는 범용 기본 세트로 시작하며, 조회·조정은 챗 명령으로 가능하고, 변경은 새 생성분부터 적용된다(소급 재생성 없음). 이 방식으로 **어떤 도메인의 자료를 넣어도 수동 스키마 작업 없이** 생성이 진행되며, "기존 유형 우선 재사용" 규칙이 교차 자료 연결(성공 기준 6)을 보호한다.
- **S4 (검수 1단계 — 구조 검수)**: 사용자가 챗에서 검수를 요청하면 → 대기 중인 JSON **목록이 제시되고, 파일 1개 단위로** 크롬 3D 앱에 자동 표시된다(드래그앤드롭 불필요 — 수동 대체 수단으로는 유지). 사용자가 구조(유형·개수·명백한 오류)를 눈으로 확인한 뒤 챗에서 승인 또는 반려를 말한다. **승인·반려 명령은 대상 파일명을 명시해 실행**된다(챗 AI가 파일명을 채워 호출). **승인** → `Reviewed/`로 이동. **반려** → `Rejected/`로 이동(삭제 아님)하고 같은 자료의 재생성을 이어서 1회 자동 실행한다. **같은 자료가 3회 누적 반려되면 자동 재생성을 멈추고 보류로 안내**한다(스키마·지시문 조정 후 별도 지시로 재시도).
- **S5 (Neo4j 주입)**: 사용자가 챗에서 주입을 지시하면 → `Reviewed/`의 승인분이 Neo4j(AuraDB 클라우드 인스턴스)에 반영된다. **MVP에서 주입 명령은 항상 "Reviewed/ 전체 기준 재조립(재빌드)"과 동일하게 동작**한다(증분 주입은 후순위) — 같은 명령을 몇 번 실행해도 결과가 같다(멱등). **삭제 범위는 본 도구가 주입한 데이터(출처 속성 보유분)만이며, 도구 전용 데이터베이스 사용을 기본 전제로 한다** — 같은 DB의 다른 데이터를 건드리지 않는다. **동일 엔티티 병합**: 정규화된 (이름, 노드 유형) 기준으로 병합하고, 속성은 보존·보강, 중복 관계는 제거한다 — 서로 다른 자료에서 나온 같은 엔티티(예: 두 문서의 "탄지로")가 하나로 연결되어야 자료를 넘나드는 지식이 성립한다. **출처 속성**: 각 노드·관계에 Reviewed JSON 파일명(재빌드 제외 키)과 원 Input 파일명을 기록한다. 반려·정리가 필요하면 챗 지시로 해당 JSON을 제외하고 재빌드한다.
- **S6 (질의응답 + 경로 하이라이트 ★핵심, 검수 2단계 — 의미 검수 겸함)**: 사용자가 **Claude 앱 또는 ChatGPT 데스크탑 앱(Codex)** 에서 질문하면 → 로컬 MCP 서버(*MCP = Claude·ChatGPT 앱에 우리가 만든 도구를 꽂아 쓰게 해주는 표준 연결 방식*)가 Neo4j에서 그래프 검색을 수행하고 → 답변과 함께 크롬에 열린 3D 앱이 **3가지 시각 상태**로 표시된다: **① 검색 무관 노드·관계 = 어둡게(dim)** **② 1층(검색에 참고된 부분) = 은은한 표시** — AI의 지시 준수와 무관하게 검색 시점에 시스템이 무조건 푸시하는 누락 없는 보장선, 2층과 한눈에 구분되어야 함 **③ 2층(답변이 실제 인용한 경로) = 강조 + 이동 파티클** — 답변의 구조화 인용을 1층과의 교집합으로 검증한 것만, 이웃으로의 확장 강조는 하지 않음. 인용이 없거나 검증에서 탈락하면 1층만 표시되고 그 사실이 안내된다. 화면에 1층의 일부가 없으면 **"N개 중 M개 표시"(N = 1층 기준)를 3D 앱 화면에** 안내한다. **주입 직후 이 시나리오로 질문을 던져 의미를 검수하는 것이 필수 절차**다 — 의미 검수는 사용자 판단이며 시스템은 검수 상태를 별도 기록하지 않는다. **반려 판단 가이드**: 하이라이트된 경로 자체가 원문과 다를 때(그래프 오류)만 반려하며, 검색이 경로를 못 찾는 것은 반려 사유가 아니다(검색 품질 이슈로 별도 개선). 반려 시 해당 JSON 제외 재빌드 후, 그 자료는 S4와 같은 재생성 경로를 따른다.
- **부속 명령 (자료 제거)**: 사용자가 챗에서 특정 자료의 제거를 지시하면 → 해당 자료의 Input/·Generated/·Reviewed/·**Rejected/**·원장 기록과 DB 반영분(재빌드)이 일괄 처리된다(**완전 제거** — 민감 자료 제거 시 반려 사본까지 남기지 않기 위함, 2026-08-21 오너 승인 개정). 제거 시 "재수집 허용"(원장에서 삭제)과 "영구 차단"(원장에 차단 표시) 중 선택한다.

## 5. 성공 기준 ("이게 되면 1차 완성")

1. **수집**: URL 1개 + 상한 10으로 실행하면 10개 이하의 MD가 파일명 규칙대로 생성되고, 재실행 시 기수집분은 건너뛰며 실패분은 재시도된다 (S1)
2. **추출**: 텍스트가 포함된 디지털 PDF 1건·문자가 선명한 이미지 1건을 입력하면, 외부 전송 없이 규칙에 맞는 MD가 프론트매터와 함께 생성된다 (S2 — 판정은 이 성격의 자료로 수행)
3. **생성**: `Input/` 자료가 스키마 검증을 통과하는 KG JSON이 되어 Input 1파일당 1개씩 `Generated/`에 저장된다. **두 엔진(Codex/Claude) 각각 최소 1회 검증** — 병목 시 순서 조정은 가능하나 1차 완성 선언 전 양쪽 확인 (S3)
4. **조작 원칙**: 챗 검수 요청 → 3D 앱 자동 표시 → 챗 승인 → 주입까지 파일 복붙·드래그앤드롭·Neo4j 수동 작업 없이 완료된다 (S4·S5)
5. **하이라이트 ★핵심**: **Claude 앱과 Codex 각각에서** 질문 시 1층 하이라이트가 무조건 표시되고, 답변에 구조화 인용이 있으면 2층 강조·파티클이 표시되며, 인용이 없거나 검증 탈락 시 그 사실이 안내된다. 1차 완성 선언은 양 클라이언트 충족 후 (S6)
6. **교차 자료 연결**: 서로 다른 두 자료에 걸친 질문에서 경로가 자료 경계를 넘어 이어져 하이라이트된다 (S5 병합 규칙의 검증)
7. **되돌리기**: 의미 검수에서 반려하면 챗 지시만으로 재빌드되어 DB가 반려분 없는 상태로 복원되고, 같은 JSON을 재주입해도 결과가 같다 (S5·S6)
8. **실패 보고**: 실패 케이스 1건 이상에서 성공/실패 요약이 챗 응답으로 보고됨을 확인한다 (실패 보고 원칙)
9. **클론 재현**: 클론 사용자가 README만 보고 예시 데이터 데모(주입 → 질문 → 하이라이트)를 재현할 수 있다

## 6. 리스크와 열린 질문

- **구독 사용량 한도**: Codex(5시간 롤링)·Claude(챗과 공유) 한도가 배치·대화를 제한할 수 있음 → 체크포인트 배치 + **엔진 상호 전환**(한 엔진 소진 시 다른 엔진으로 자동 전환 — 두 구독 잔여 한도 최대 활용, 2026-08-21 결정)으로 완화. 단 Claude로 생성 중인 시간대에는 생성 배치가 개발·검수 챗과 같은 Claude 한도를 공유한다. 도구 출력 경량화는 **2층 인용에 필요한 최소 정보(노드 id·이름·관계 유형)를 보존하는 범위**에서 TECH-SPEC이 정한다. 병목 시 API 크레딧(후순위)
