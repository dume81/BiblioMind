## 1. 판정 세션 운영 — **새 채팅이냐 `/clear`냐**

**결론: 둘 중 아무거나 써도 된다.** 목적은 하나 — **직전 대화의 검색 결과를 모델의 눈앞에서 치우는 것**이다. 새 채팅은 확실하고, `/clear`도 같은 목적을 달성한다(2026-08-21 판정에서 E1·E2·E3를 `/clear`로 실행하고 "청정"으로 기록한 실적이 있다 — `[문서] spike-judgment-log.md:30~32`).

### 어느 문항에 필요한가 — **전부는 아니다**

| 문항군 | 세션 처리 | 왜 |
|---|---|---|
| **D1·D2·D3 · E1·E2·E3** (6문) | **문항마다 새 채팅 또는 `/clear`** | 이 6문이 재는 것은 **①호출 여부**다. 앞 문항의 검색 결과가 대화에 남아 있으면 모델이 "이미 아는데 굳이?" 하고 도구를 건너뛴다 — 지표가 무효가 된다 |
| **A3·B1·B2·B4·C4** (5문) | **연속 대화 그대로 진행** | 이 5문이 재는 것은 **②시드·③인용·④3상태**이고, 셋 다 **도구가 돌려준 값**이라 대화 맥락에 오염되지 않는다 |

### ⚠️ 대신 생기는 부작용 — **⑤ 소요 시간이 부풀어 오른다**

개선 전 실측에서 **`/clear` 직후 첫 질문은 12~16초**, 연속 대화 안에서는 **5~7초**였다(컨텍스트·규칙을 새로 읽는 시간). 예산 10초를 넘긴 4건은 **전부 새 컨텍스트의 첫 질문**이었다 `[문서] spike-judgment-log.md:67`.

⇒ **⑤는 두 모집단을 섞지 말고 나눠 적는다.**

| 모집단 | 개선 전 기준선 | M4 판정 |
|---|---|---|
| 새 컨텍스트 첫 질문(D·E군 6문) | 12~16초 | 이 범위를 크게 벗어나지 않으면 통과 |
| 연속 대화(A·B·C군 5문) | 5~7초 (전체 중앙값 **6.4초** · 평균 8.0초) | **중앙값 예산 10초 이내** |

섞어서 중앙값을 내면 **개선과 무관한 이유로 미달이 뜬다.** 이것이 이번 실행표에서 가장 틀리기 쉬운 지점이다.

**A3 → B1 → B2 → B4 → C4** (연속 대화 5문, 문항마다 ④ 대조) → **`/clear`** → **D1** → `/clear` → **D2** → `/clear` → **D3** → `/clear` → **E1** → `/clear` → **E2** → `/clear` → **E3**

### ⚠️ A3에서 **복원 문구가 안 뜨는 것이 정상이다**

키워드 손상은 **모델이 매번 일으키는 것이 아니다**(실측 손상률 5.4%). A3에서 모델이 `일륜도`를 정상으로 넘기면 그냥 **T1 적중**이고 재검색 문구는 뜨지 않는다 — **이것이 통과다.** 반대로 손상이 재발하면 아래 문구가 뜨고, 그때도 **시드 1건(일륜도:T1)으로 적중**해야 한다.

```
키워드 자동 재검색 1건: '일륨도'는 그래프에 없어, 이 호출의 question에서
자모 1개만 다른 '일륜도'로 다시 검색함 (자동 추정 — 확정된 오타 판정이 아니다)
```

손상이 실제로 재발하면 **그 자체가 귀중한 관측 표본**이므로 비고에 반드시 남긴다(현재 표본 n=2).

### 회귀로 오인하지 말 것 — 개선 후 **새로 나타나는 문구 2종**

| 문구 | 언제 | 성격 |
|---|---|---|
| `키워드 자동 재검색 N건: …` | 손상 키워드가 복원됐을 때 | **설계된 출력** |
| `1층의 n건 중 m건을 인용했습니다 — 2층이 1층과 거의 같아 강조 대비가 낮습니다.` | 인용이 1층의 50%를 넘을 때 | **설계된 출력**(옛 `과잉 인용 의심`의 서술형 교체본). A3처럼 1층이 작은 문항에서 정상적으로 뜬다 |

반대로 **사라져야 할 문구**: `과잉 인용 의심` · `0.5 스파이크 준비`. 둘 중 하나라도 보이면 구버전이 돌고 있는 것이다.

`spike-judgment-log.md`의 기존 표와 **같은 열 구성**이며, ④ 열만 자동 대조 결과로 바뀐다.

| 문항 | 질문 일치 | ①호출 | ②시드(계층) | ③인용 | ④3상태(자동) | ⑤소요 | 모델 | 세션 | 비고 |
|---|---|---|---|---|---|---|---|---|---|
| A3 | ✓/✗ | ✓/✗ | 이름 + T1/T2/T3 | n/m verified | `check-highlight` k/11 | 초 | Opus 5 등 | 연속 | 복원 문구 유무·특이사항 |

- **②시드**: 도구 반환 내역에서 `시드 N건(이름:계층)` 문자열을 **직접 확인**하면 `확정`, 구조상 확실하나 미확인이면 `추정`으로 적는다.

## 4. 판정 ④ 자동 대조 — 육안 대신 이 절차

문항 직후(다음 문항 넘어가기 **전**) 실행한다. `data/runtime/last-searches.json`이 **5건 롤링**이라 미루면 밀려난다.

1. 크롬 콘솔에서 스냅샷을 파일로 저장 — 또는 판정 세션의 브라우저 도구로 같은 값을 뽑는다.
   ```
   copy(JSON.stringify(window.__bibliomind))
   ```
2. 저장한 파일로 대조한다(저장소 루트에서).
   ```
   node scripts/check-highlight.js --snapshot snapshot.json
   ```
3. 출력의 마지막 줄 `판정 ④: k/11 통과`를 기록 양식에 옮긴다.

**무엇을 검사하나**: searchId·질문 원문 일치 / 1층 노드·관계 kgid 집합이 푸시한 것과 동일 / N 일치 / 2층 ⊆ 1층 / 렌더 1층·2층 겹침 없음(2층 우선 규칙) / M == 실제 렌더 총수 / citation 상태와 2층 존재의 정합.

**`ℹ N/M 격차` 안내는 실패가 아니다** — 현재 화면에 없는 kgid(필터로 숨겨졌거나 그래프가 낡음)의 내역이며, 그것이 곧 화면의 `N개 중 M개 표시 중` 문구의 근거다.

**이 도구가 증명하지 않는 것**: 앱이 **어느 집합을 어느 상태로 판정했는가**까지다. 그 판정이 **실제로 그 색으로 칠해졌는지**는 증명하지 않는다(스냅샷과 색 적용은 평행 경로 — TECH-SPEC §7.9 한계). 그 구간은 **대표 2~3문항만 육안**으로 본다.
