## 2026-08-21: 사용자 답변 5건 게이트 통과 — 통과 조건 3건 확정

- **결정**: 인터뷰 답변 5건(하이라이트 정의·파일명 규칙·검수 흐름 수정)을 전문가 3인 게이트(파이프라인·시각화·아키텍트, 기존 코드 직접 확인 포함) "조건부 통과" 판정에 따라 아래 수정 조건과 함께 채택한다.
  1. **파일명 규칙 v2**: 배치(실행) 시작 시각으로 타임스탬프 1회 고정 + 실행 내 순번 — `yyyymmddhhmmss_메인이름_p01.md`. 메인 이름 = 등록 도메인의 2단계 라벨(tldextract 기준: www.bibliomind.com→bibliomind, blog.bibliomind.com→bibliomind, bibliomind.co.kr→bibliomind). **원본 URL·페이지 제목·수집 시각은 파일 첫머리 YAML 프론트매터에 필수 기록**(검수 시 출처 역추적의 전제). PDF 제목은 Windows 금지 문자 제거 등 sanitize 후 사용, 원제목은 프론트매터 보존.
  2. **검수 2단 구조 + 주입 롤백**: 검수-전(JSON 파일 모드) = 구조 검수 — 질문 기반 하이라이트 없음(사용자 skip 판단이 기술적으로도 정확함을 확인), 기존 유형·속성 하이라이트 활용. 검수-후(Neo4j 모드) = 질문 기반 의미 검수(필수). 주입 후 반려가 정상 경로가 되므로 **주입 되돌리기 = "승인 JSON 재빌드" 방식**(Reviewed/ 폴더가 원본 진실, Neo4j는 파생물 — 반려 시 해당 JSON 제외 후 전체 재주입) 채택. 주입 시 노드·관계에 출처 파일명 속성 기록.
  3. **하이라이트 스펙 = "쿼리 하이라이트 레이어" + 2계층**: 스타일 2종 동시 선택이 아니라(현 앱은 스타일 단일 선택 구조), 어떤 스타일 위에도 겹쳐지는 별도 강조 레이어로 구현 — 집합 밖은 dim(이웃 하이라이트의 시각 문법 재사용, 1-hop 이웃 확장은 안 함) + 집합 내 관계에만 방향 이동 파티클(per-link accessor). 2계층: 1층 = 검색 서브그래프를 결정적으로 푸시(은은한 강조, 누락 없는 보장선), 2층 = 답변의 구조화 인용을 1층과의 교집합으로 검증한 것만 강조(이웃+파티클). 시각화 앱에 하이라이트 수신 채널 신설(POST /api/highlight + SSE 구독) 및 부분 매칭 시 "N개 중 M개 표시" 안내.
- **근거**: docs/interview-round1.md 8절 게이트 결과. 시각화 검증은 vizStyles.js·Graph3D.jsx·HighlightPanel.jsx·mapper.js 실코드 확인 기반.
- **영향**: PRD(Phase 0)·TECH-SPEC(Phase 1)에 위 조건이 요구사항·설계 제약으로 반영된다.

2. **⛔ robots 차단 우회 — 실제 예절 위반이 발생했다.** `normalizeUrl`이 경로 끝 `/`를 지우므로(§2.4.4 정규화 규칙) `/api/` 가 큐에 `/api` 로 들어갔고 `Disallow: /api/` 규칙에 매칭되지 않아 **사이트가 막은 경로에 요청을 보냈다.** 정규화는 멱등 키에 필요하므로 되돌리지 않고 **판정 쪽에서 슬래시 변형까지 검사**하도록 `robotsDisallows()` 신설(회귀 테스트 `#16~#21` 6건). **잘못 수집한 MD 2건과 원장 엔트리 2건은 삭제했다.**
3. **요약이 거짓 안내를 했다** — *"max_pages를 올리면 이어서 수집합니다"*. 멱등 스킵은 **요청을 생략**하므로 그 페이지의 링크가 다시 발견되지 않아 재실행은 시작 페이지에서 끝난다. 사실대로 고치고(`--force` 필요) **`--force --max-pages 13` → 13건 수집으로 실증**했다. M3·슬라이스 2에 이은 **"틀린 안내" 3번째 사례**.

### 설계 공백 (등재 — 결정 대상)

멱등 스킵이 요청을 생략하는 한 **재실행만으로는 남은 큐를 이어받을 수 없다.** 현재 회피책은 `--force`(전체 재수집 — 무키 저율 호출에서는 비용이 크다). 정공법은 ①큐 잔여를 원장에 저장하거나 ②스킵된 페이지의 **저장된 MD에서 링크를 재추출**해 네트워크 없이 BFS를 잇는 것이다. ②가 §1.5의 "요청 생략" 규칙을 지키면서 문제를 푼다. **TECH-SPEC §1.5 개정이 선행**이므로 오너 결정 사항으로 올린다.

## 2026-08-22: **5-B 판정 정정 — `rate_limit`은 오탐이었다** (오너 반증)

### ⛔ 실사고 적발 — `kg_generate`는 챗에서 **한 번도 동작한 적이 없었다**

**[실측]** 원시 JSON-RPC로 호출하자 매번 `-32602 Invalid tools/call result: expected object, received string`. 원인은 슬라이스 5-A의 반환문이 `toolContent()`를 거치지 않고 **문자열**을 돌려준 것(+ `tool` 인자 누락으로 요약 첫 줄이 *"[bibliomind] undefined 결과"*).

**기존 검증이 못 잡은 이유 — 둘 다 표면만 봤다**: ① `npm run mcp:smoke`는 `tools/list`만 호출한다(등록 목록은 정상이었다) ② 단위 테스트는 도메인 함수(`generateKg`)만 부른다(도구 핸들러를 안 지난다). **6건 생성은 스크립트가 `generateKg`를 직접 부른 것이라 이 결함을 드러내지 않았다.**

**수리 + 가드**: `toolContent(buildSummary({tool, …}), data)`로 교정하고, 등록된 **9종 전체**의 핸들러를 실제로 호출해 **SDK 자신의 `CallToolResultSchema`** 에 통과시키는 시험을 만들었다(내가 손으로 쓴 형식 단언이 아니라 클라이언트가 실제로 쓰는 그 스키마).

**가드 자체를 뮤테이션으로 검정했다 — 그리고 1차 시도는 내 착각이었다**: 고의 회귀를 심고 돌렸더니 15/15 통과라 "가드가 약하다"고 판단했으나, 실제로는 **셸 이스케이프 때문에 주입이 조용히 no-op** 됐던 것이다(집계자 실수 #5의 재발 — 셸 서식). Edit 도구로 다시 주입하니 **2건 실패로 명확히 살해**됐다. 다만 이 소동이 진짜 결함 하나를 드러냈다: 초판 시험은 `kg_generate`의 **실패 분기만** 밟고 있었다(격리 폴더에 `schema.json`이 없어 catch로 빠졌다). `schema.json`을 깔아 **정상 분기**도 밟게 고쳤고, 뮤테이션 실행에서 실패 분기 시험(#6)은 통과·정상 분기 시험(#4·#5)만 실패해 **이 교정이 필요했음이 증명**됐다.

### 부수 적발 — 산출물 `meta`가 없었다

§2.2가 요구하는 `meta`(`input_file`·`schema_version`·`engine`·`generated_at`)를 **생성기가 찍지 않고 있었다**(`validateKgSchema`는 `requireMeta:false`로 우회 호출 중). `review_list`의 `engine` 필드(§4.3-4)가 이것을 읽으므로 슬라이스 6에서 드러났다. 생성기가 찍도록 수리했다 — **엔진에게 맡기지 않는다**(지어낼 수 있고, 한도 전환 후 실제 엔진은 파이프라인만 안다).

**기존 6건은 추측으로 채우지 않는다** — `engine: null`로 표시하고 요약에 *"엔진 미기록 6건 — meta 스탬프 도입 전 생성분"* 을 붙였다. 미채택 대안 = 로그로 유추해 소급 기입(생성물 내용을 사후 조작하는 것이라 기각).

### 범위 밖으로 미룬 것 (정직 기재)

- **§4.3-7 ②의 자동 `kg_rebuild`는 실행하지 않는다** — 주입기가 슬라이스 7 몫이다. 대신 승인분 반려 시 *"이 자료는 Neo4j에 아직 남아 있습니다"* 를 **명시 고지**한다. 조용히 넘어가면 반려된 자료가 그래프에 남은 줄 모른다.
- **승인·반려의 실제 판단은 하지 않았다** — 이사님의 `data/Generated` 6건은 검수 판단이 필요한 실물이다. e2e는 그 사본을 격리 폴더에서 왕복시켜 **기전만** 증명했다. 실제 승인·반려는 이사님 몫으로 남긴다.
- **자동 재생성의 실엔진 경로는 미실측** — 가짜 구현으로 "1회·원본 Input 지정" 호출만 확인했다(구독 미소모). 실엔진 왕복은 이사님이 실제로 반려할 때 자연 검증된다.
