## 2026-08-21: 사용자 답변 5건 게이트 통과 — 통과 조건 3건 확정

- **결정**: 인터뷰 답변 5건(하이라이트 정의·파일명 규칙·검수 흐름 수정)을 전문가 3인 게이트(파이프라인·시각화·아키텍트, 기존 코드 직접 확인 포함) "조건부 통과" 판정에 따라 아래 수정 조건과 함께 채택한다.
  1. **파일명 규칙 v2**: 배치(실행) 시작 시각으로 타임스탬프 1회 고정 + 실행 내 순번 — `yyyymmddhhmmss_메인이름_p01.md`. 메인 이름 = 등록 도메인의 2단계 라벨(tldextract 기준: www.bibliomind.com→bibliomind, blog.bibliomind.com→bibliomind, bibliomind.co.kr→bibliomind). **원본 URL·페이지 제목·수집 시각은 파일 첫머리 YAML 프론트매터에 필수 기록**(검수 시 출처 역추적의 전제). PDF 제목은 Windows 금지 문자 제거 등 sanitize 후 사용, 원제목은 프론트매터 보존.
  2. **검수 2단 구조 + 주입 롤백**: 검수-전(JSON 파일 모드) = 구조 검수 — 질문 기반 하이라이트 없음(사용자 skip 판단이 기술적으로도 정확함을 확인), 기존 유형·속성 하이라이트 활용. 검수-후(Neo4j 모드) = 질문 기반 의미 검수(필수). 주입 후 반려가 정상 경로가 되므로 **주입 되돌리기 = "승인 JSON 재빌드" 방식**(Reviewed/ 폴더가 원본 진실, Neo4j는 파생물 — 반려 시 해당 JSON 제외 후 전체 재주입) 채택. 주입 시 노드·관계에 출처 파일명 속성 기록.
  3. **하이라이트 스펙 = "쿼리 하이라이트 레이어" + 2계층**: 스타일 2종 동시 선택이 아니라(현 앱은 스타일 단일 선택 구조), 어떤 스타일 위에도 겹쳐지는 별도 강조 레이어로 구현 — 집합 밖은 dim(이웃 하이라이트의 시각 문법 재사용, 1-hop 이웃 확장은 안 함) + 집합 내 관계에만 방향 이동 파티클(per-link accessor). 2계층: 1층 = 검색 서브그래프를 결정적으로 푸시(은은한 강조, 누락 없는 보장선), 2층 = 답변의 구조화 인용을 1층과의 교집합으로 검증한 것만 강조(이웃+파티클). 시각화 앱에 하이라이트 수신 채널 신설(POST /api/highlight + SSE 구독) 및 부분 매칭 시 "N개 중 M개 표시" 안내.
- **근거**: docs/interview-round1.md 8절 게이트 결과. 시각화 검증은 vizStyles.js·Graph3D.jsx·HighlightPanel.jsx·mapper.js 실코드 확인 기반.
- **영향**: PRD(Phase 0)·TECH-SPEC(Phase 1)에 위 조건이 요구사항·설계 제약으로 반영된다.

## 2026-08-22: 결정 요청 방식 — **한 번에 1건 순차 제시** (오너 지시)

- **오너 회신**: *"너무 많은 결정을 요구하니 가장 중요한 것부터 하나씩 결정할 수 있게 해줘."*
