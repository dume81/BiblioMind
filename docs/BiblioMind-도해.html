유저 플로우

User Flow — 두 표면을 오가는 9단계 여정

이 앱의 조작은 전부 챗에서 말로 하고(조종석), 크롬 3D 앱은 결과를 보여주기만 합니다(화면). 파일 복붙·드래그앤드롭·Neo4j 수동 작업은 없습니다 — 1회성 설치만 예외.

정보구조도

Information Architecture — 명령 · 화면 · 데이터의 계층

전통적 메뉴 트리 대신, 이 앱의 "메뉴"는 챗 명령 15종이고 "콘텐츠"는 3D 화면 요소와 데이터 폴더입니다. 기존은 이미 동작하는 것, 신설은 이번 설계로 추가되는 것.

챗 명령 15종 MCP 도구 — 조종석

  • 수집 (2)
  • collect_web — URL → 크롤 → Input/
  • collect_docs — PDF·이미지 → 로컬 추출
  • 생성 (1)
  • kg_generate — KG JSON 생성 · 체크포인트 · 스키마 자동 도출
  • 검수 (4)
  • review_list — 대기 목록·반려 이력
  • review_show — 3D 앱에 표시
  • review_approve — Reviewed/ 이동
  • review_reject — Rejected/ + 재생성 1회/3회 보류
  • 주입 (1)
  • kg_rebuild — 전체 재조립(멱등)
  • 제거 (1)
  • source_remove 파괴적 — 매번 확인
  • 스키마 (2)
  • schema_get · schema_update — 조회·수동 조정
  • 질의·하이라이트 (3)
  • kg_search — 검색 + 1층 무조건 푸시
  • kg_cite — 인용 검증(∩1층) + 2층 푸시
  • highlight_clear — 해제
  • 상태 (1)
  • kg_status — 파이프라인·DB·연결 진단

저장소 · 데이터 구조 GraphRAG_1st 모노레포

  • 패키지 4 + 스크립트
  • visualization-3d/ — 기존 앱 + 허브·레이어 확장
  • pipeline/ — 수집·추출·생성·주입 실행 엔진
  • mcp-server/ — 챗 조종석 (도구 15종)
  • shared/ — 정규화·검증·스키마 시드 단일 진실
  • scripts/setup.js — 최초 1회 부트스트랩

  • data/ 커밋 금지 — 로컬 전용
  • Input/ — 수집·추출된 MD
  • Generated/ — 생성된 KG JSON (완전한 것만)
  • Reviewed/ — 승인분 = 재빌드의 원본 진실
  • Rejected/ — 반려분 보관 (삭제 아님)
  • ledger.json — 원장: 수집 상태·차단·반려 횟수
  • schema.json — 전역 스키마 (AI 자동 등재 대상)
  • runtime/ · tmp/ · .tmp/ · ocr-cache/ — 검색 상태·엔진 임시·원자 쓰기 스테이징·OCR 캐시
  • 데이터 수명주기
  • Input → Generated → Reviewed → Neo4j
  • 반려는 Rejected/로, 되돌리기는 Reviewed/ 기준 재조립

아키텍처

Architecture — 컴포넌트와 데이터 흐름

챗 클라이언트 2종이 같은 MCP 서버 하나에 꽂히고, MCP 서버가 파이프라인·Neo4j·시각화 허브를 조종합니다. 점선 테두리는 데이터가 밖으로 나가는 외부 서비스입니다.
