## 1. 문제 — 무엇이 6번 재발했나

같은 실수 유형이 반복됐다: **실패할 수 없는 시험을 만든다.**

- 2단 10문이 판별력 0이었다(어떤 회귀도 못 잡음)
- M4 재캡처가 직전 캡처와 MD5 동일이었다(증분 0)
- 시드 임계값 ≥80%가 개선 **전** 실적 93.3%보다 낮았다(퇴행해도 통과)
- 합격선 ①에 채점란이 없었고, ⑤에 측정 수단이 없었다

- 합격선 정본이 두 문서 사이에서 순환 참조였다

**기각된 대책**: 새 규칙 문서. 근거 = *"기록은 6번 재발을 못 막았다."* 같은 날 교훈을 보유한 상태에서 셸 서식 사고가 재발한 실측이 있다(`DECISIONS.md` 실수 기록 ⑤).

### 왜 기존 21케이스는 판별력이 없었나 (원인 규명)

- `#8 '무잔'` · `#16 '호흄'` — 둘 다 **2글자**라 가드3(최소 3글자)에서 먼저 걸러진다. 가드4나 거리 상한을 꺼도 결과가 `null`로 같아서 **뮤턴트를 구분하지 못한다.**
- `#9 '일륨도' + '검증: 일륨도'` — 질문 속 후보가 **거리 0**(자기 자신)이라 "거리 정확히 1" 조건에서 이미 탈락. 역시 가드4를 꺼도 `null`.

⇒ **살해 케이스의 요건**: 가드를 껐을 때 `null`이 **아닌 값이 실제로 나오는** 입력이어야 한다. 통과하는 것만으로는 시험이 아니다.

### 파싱 실패 은폐 경로 (수리 전 실제 동작)

수집기가 도구 출력을 못 읽으면 `seeds = []` → `seedCount: 0` · `unmatched: []`로 기록됐다. `unmatched`가 **빈 배열**이라 survey가 그것을 유효한 목록으로 믿고, 손상 키워드를 `includes()` 실패 → **"이 키워드가 시드를 얻음(손상 무해)"** 으로 분류했다. 즉 **읽기 실패가 거짓 부재 후보를 조용히 지웠다.**

수리: `parseFailed` 플래그 + `seedCount: null` + `unmatched: null`, survey는 이를 **미측정**(제3의 값)으로 세고 `pass` 조건에 포함한다 — 8조 제4조의 4값 판정과 일치.

## 4. 검출력의 천장 — 오프라인으로 죽일 수 없는 것 (실측)

생존 5건은 성격이 서로 다르다. **뭉뚱그려 "5건 생존"이라고만 적으면 다시 실패할 수 없는 시험이 된다.**

| 생존 뮤턴트 | 성격 | 근거 |
|---|---|---|
| `GUARD4_OFF` | **동치 뮤턴트 — 죽일 수 없는 것이 정상** | `if (q.includes(kw)) return null;` 첫 줄이 루프 안 `if (cand === kw) return null;`에 완전히 포섭된다. kw는 가드2로 구두점을 포함할 수 없으므로 q의 부분문자열이면 반드시 한 run 안에 있고, 창 열거가 항상 먼저 잡는다. **차분 검사 1264쌍 출력 차이 0건** [실측] ⇒ 테스트 구멍이 아니라 **중복 코드** |
| `T3_ON_RESTORE` | 살아 있는 DB 필요 | 넷 다 `runSearch(session, …)`(`searchEngine.js:282~`) 내부다. 오프라인 가드(vitest 단위 + check-keywords)는 **구조적으로 도달할 수 없다** |
| `HITPATH_OPEN` | 〃 | 〃 |
| `SEEDS_TOTAL_3` | 〃 | 상한 절단이 `runSearch` 내부(`:328`)에서 일어난다 |
| `HOPS_0` | 〃 | `runSearch` 기본 인자(`:282`) |
